# MoErgo Go60 Specifics

What sits on top of (or diverges from) base ZMK for this keyboard and this repo.

## The MoErgo fork — why docs version matters

Firmware builds against **`github.com/moergo-sc/zmk`**, MoErgo's fork of ZMK for the Glove80 and Go60 — *not* upstream `zmkfirmware/zmk`. The fork:

- **Lags upstream.** Its feature set corresponds to the **ZMK v0.3 era** → consult `v0-3-branch.zmk.dev`, never current `zmk.dev`, before promising a feature or property exists. When in doubt, grep the fork's source.
- **Adds Nix build infrastructure**: `default.nix` exposes a `zmk` derivation with `.override { board = ...; keymap = ...; kconfig = ...; }` plus `combine_uf2` to merge left+right images into one flashable UF2. Prebuilt artifacts come from the `moergo-glove80-zmk-dev` Cachix cache.
- **Provides the board definitions** `go60_lh` / `go60_rh`; matrix wiring lives there, not in this repo.
- **Adds `RGB_STATUS`** as an `&rgb_ug` command (battery/connectivity status indication on the underglow) — used by this keymap's `rgb_ug_status_macro`. Not in upstream ZMK.
- Releases are tagged like `v25.11`; `./build.sh <ref>` can target any branch/tag/SHA.

The MoErgo Layout Editor (`my.glove80.com`-style webapp for Go60) is the no-code path; this repo is the hand-edited devicetree path. The editor *generated the original keymap* (header comment says so — preserve it) and defined the `*_TKZ` (TailorKey) naming convention throughout.

## Build / flash / visualize

Full detail in `docs.md`; quick reference:

| Task | Command |
|---|---|
| Build (Docker, skip fetch) | `make build` |
| Build (Docker, full) | `./build.sh [zmk-ref]`; `REBUILD=1` / `SKIP_FETCH=1` env flags |
| Build (native nix) | `nix-build ./config --arg firmware 'import ../zmk/default.nix {}' -o combined` |
| Build (CI) | push — `.github/workflows/build.yml` attaches `go60.uf2` artifact |
| Flash | `./flash.sh` (build + copy to bootloader drive) |
| Redraw layout SVGs | `make draw` / `./draw.sh` (keymap-drawer) |
| HTML layer viewer | `make html` → `output/layout.html`; `make layers` for the popup viewer |
| Key-position identifier | `make ident` (`tools/key-id.py`) or `/layout` command |
| Token-aware keymap diff | `make diff` (`REF=<rev>` to compare against another rev) |

Caveats:

- **`flash.sh` works on macOS and Linux**: it searches `/Volumes`, `/run/media/$USER`, and `/media` for a `GO60*BOOT` drive, and on Linux auto-mounts an attached-but-unmounted bootloader partition via `udisksctl` (label lookup through `/dev/disk/by-label/`).
- Bootloader mode: hold the `&magic` key, tap the `&bootloader` key on the Magic layer. The combined UF2 contains both halves; each side's bootloader extracts its own — flash each half separately with the same file.
- One `go60.uf2` is committed at repo root and overwritten by local builds.
- `keymap-drawer/` and `output/layout.html` are regenerated (locally via a watcher/hook, and in CI via `draw.yml`) whenever the keymap changes — **stage them together with keymap edits** so renders stay in sync.

## Physical layout & key naming

60 keys per the combined matrix, positions `0–59`. Names: `<L|R>_C<col>R<row>` main grid, `<L|R>_T<1-3>` thumbs; the keymap's defines use the `POS_LH_*` / `POS_RH_*` prefix (block at `config/go60.keymap` ~lines 71–130).

- Columns **6 = outer/pinky, 1 = inner/index**; rows 1 (number row) → 4 (bottom main), row 5 is a small 3-key strip per hand; thumbs `T1` innermost → `T3` outermost.
- **Binding order within a keymap row line**: left hand C6→C1, then right hand C1→C6. Thumb line: `LH_T3 LH_T2 LH_T1 | RH_T1 RH_T2 RH_T3`.
- The `/layout` command renders the full grid with names and indices; `config/info.json` holds x/y/rotation geometry (visualizers only — **never** an input to the firmware build).

## This keymap's architecture (`config/go60.keymap`)

Generated by the Go60 Layout Editor with the TailorKey template, then hand-extended. Conventions to preserve:

- **`*_TKZ` suffix** marks TailorKey-generated behaviors/macros. Hand-authored ones (documented in `wiki/keymap-behaviors.md`) have no suffix: `qt_swap`, `td_shift_caps`, `tp`, `skq`, `semi_colon_morph`, ...
- **21 layers** (`#define LAYER_*`, ~lines 201–221): base `LAYER_HRM_macOS` (0), `Typing` (1), `Autoshift` (2), per-finger HRM layers 3–10 (Left/Right × Pinky/Ringy/Middy/Index), `Cursor` (11), `Keypad` (12), `Symbol` (13), Mouse stack 14–17 (Mouse/Slow/Fast/Warp), `Gaming` (18), `Magic` (19), `fn` (20). Re-grep before trusting these — they shift when layers are added.
- **HRM (home-row mods) architecture**: each home-row key is a bilateral hold-tap (`HRM_<hand>_<finger>_v1B_TKZ`, flavor tap-preferred, 260 ms term, `require-prior-idle-ms`, `hold-trigger-key-positions` = the *opposite* hand + thumbs, `hold-trigger-on-release`). The hold side is a macro that presses the modifier **and** momentarily activates that finger's layer (layers 3–10), so same-hand combinations remain typeable. To alter one key's *tap* output, add a new hold-tap variant rather than mutating the shared one (precedent: `HRM_right_pinky_semi_v1B_TKZ` wrapping `semi_colon_morph`).
- **`KEYMAP_OS` toggle** (~line 158): `#define KEYMAP_OS KEYMAP_OS_LINUX` (or `_MACOS`) selects `OS_MOD()`/`OS_WORD()`/`OS_LINESTART`/`OS_LINEEND`/`OS_SELTOLINEEND`/`OS_TASKSWITCH_MOD`, from which ~19 semantic constants are built (`OS_COPY`, `OS_PASTE_PLAIN`, `OS_WORD_DEL_BACK`, `OS_FIND_NEXT`, ...). **Any new OS-dependent shortcut must be added here as a semantic constant and used by name** — never inline `LG(C)`/`LC(C)` in a layer. Switching OS = flip one define + rebuild.
- **`EDITOR_HOST_OS 'M'`** is the Layout Editor's own dead bookkeeping — unrelated to `KEYMAP_OS`; leave it alone.
- **Magic layer plumbing**: `&magic LAYER_Magic 0` (hold = `&mo`, tap = `rgb_ug_status_macro` → `&rgb_ug RGB_STATUS`); `bt_0`–`bt_3` tap-dances (tap = select BLE profile via `&out OUT_BLE` + `&bt BT_SEL n`, double-tap = disconnect); `&bootloader`, `&sys_reset`, `&out OUT_USB`, RGB controls.
- **Pointing**: Cirque trackpad support via `input_processors` (e.g., `zmk,input-processor-code-mapper` for click mapping) and per-layer `&cirque_*_listener` overrides; headers `dt-bindings/zmk/pointing.h`, `input/processors.dtsi`.
- A compatibility shim `#define LAYER_Lower 0` exists only to satisfy the editor's `&lower` behavior — not a real layer.

## Editing checklist (Go60-flavored)

1. Both halves flash from the **same keymap** — there is no per-hand keymap split; `config/default.nix` feeds identical inputs to `go60_lh` and `go60_rh`.
2. Count bindings: every layer's `bindings` array must have exactly 60 entries in the physical order above.
3. New behavior nodes go inside the existing `/ { behaviors { } }` (or `macros`) blocks; match neighboring style (`name: name { ... };`).
4. `hold-trigger-key-positions` and combo `key-positions` take `POS_*` defines.
5. After editing: re-check braces/semicolons, run `make draw` to eyeball the change, then `make build` for the real compile check (the preprocessor+devicetree only fails at build time — there is no cheap standalone linter).
